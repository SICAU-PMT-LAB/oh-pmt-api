# 部署手册

照抄就能上线。所有命令都在本机（macOS）执行，通过 ssh 操作生产。

## 环境事实

| 项 | 值 |
|---|---|
| 主机 | `ubuntu@124.222.217.211` |
| 密钥 | `~/.ssh/ubuntu.pem` |
| 站点 | `https://api.hhy.homes` |
| 应用目录 | `/opt/oh-pmt-api` |
| systemd 单元 | `oh-pmt-api.service` |
| 应用日志 | `/opt/oh-pmt-api/logs/q2a.log`（**不是 journald**） |
| 数据库 | `/opt/oh-pmt-api/data/oh-pmt-api.db` |
| 环境文件 | `/etc/qoder2api/env` |
| nginx 站点 | `/etc/nginx/sites-enabled/api.hhy.homes` |
| Python | 系统 `/usr/bin/python3`（3.12）；无虚拟环境、无第三方依赖 |

systemd 关键项：

```
WorkingDirectory=/opt/oh-pmt-api
Environment=PMT_HOST=127.0.0.1
Environment=PMT_PORT=8791
Environment=PMT_DATA=/opt/oh-pmt-api/data
Environment=PMT_TRUST_FORWARDED=1
ExecStart=/usr/bin/python3 src/server.py
Restart=always
StandardOutput=append:/opt/oh-pmt-api/logs/q2a.log
```

`/etc/qoder2api/env` 里只有一行 `Q2A_ADMIN_TOKEN=...`，当前版本已不读这个变量
（改为账号密码登录），保留是为了兼容。

**生产目录不是 git 仓库。** 不要在那边 `git pull`，也不要在那边改代码——
所有改动都在本地仓库做好，然后 scp 覆盖。

注意 `/opt/oh-pmt-api/` 根目录还留着旧版的 `server.py`、`store.py`、`admin.html`
等文件（2026-10-25 之前的结构）。**实际运行的是 `src/` 与 `web/` 下的文件**，
改错位置不会生效，排查时先确认路径。

## 三类改动，三种流程

### 只改前端（`web/*.html`、`web/assets/*`）

不用重启服务。

```bash
cd ~/Documents/oh-pmt-api
scp -i ~/.ssh/ubuntu.pem web/assets/ui.css ubuntu@124.222.217.211:/tmp/ui.css
ssh -i ~/.ssh/ubuntu.pem ubuntu@124.222.217.211 '
  cd /opt/oh-pmt-api
  cp web/assets/ui.css web/assets/ui.css.bak-$(date +%Y%m%d-%H%M%S)
  cp /tmp/ui.css web/assets/ui.css && rm -f /tmp/ui.css
'
curl -s https://api.hhy.homes/assets/ui.css | head -5
```

验证线上生效：直接 `curl` 静态资源看内容，不要只看 HTTP 200。

### 改后端（`src/*.py`）

要重启。先备份、再语法检查、再重启。

```bash
cd ~/Documents/oh-pmt-api
python3 -m unittest discover -s tests

ssh -i ~/.ssh/ubuntu.pem ubuntu@124.222.217.211 '
  cd /opt/oh-pmt-api
  cp src/server.py src/server.py.bak-$(date +%Y%m%d-%H%M%S)
'
scp -i ~/.ssh/ubuntu.pem src/server.py src/store.py ubuntu@124.222.217.211:/opt/oh-pmt-api/src/

ssh -i ~/.ssh/ubuntu.pem ubuntu@124.222.217.211 '
  cd /opt/oh-pmt-api
  for f in src/server.py src/store.py; do
    python3 -c "import ast,sys;ast.parse(open(sys.argv[1]).read())" "$f" || exit 1
  done
  sudo systemctl restart oh-pmt-api
  sleep 2
  systemctl is-active oh-pmt-api
  curl -s -o /dev/null -w "health %{http_code}\n" localhost:8791/health
'
```

### 改数据（价格、限额、回填）

先备份数据库，并且把 `-wal`/`-shm` 一起算进去。

```bash
ssh -i ~/.ssh/ubuntu.pem ubuntu@124.222.217.211 '
  cd /opt/oh-pmt-api
  TS=$(date +%Y%m%d-%H%M%S)
  cp data/oh-pmt-api.db data/oh-pmt-api.db.bak-$TS
  [ -f data/oh-pmt-api.db-wal ] && cp data/oh-pmt-api.db-wal data/oh-pmt-api.db-wal.bak-$TS
  echo "备份 $TS"
'
```

回填历史缺价用 `tools/backfill_cost.py`，默认 dry-run：

```bash
scp -i ~/.ssh/ubuntu.pem tools/backfill_cost.py ubuntu@124.222.217.211:/opt/oh-pmt-api/tools/
ssh -i ~/.ssh/ubuntu.pem ubuntu@124.222.217.211 'cd /opt/oh-pmt-api && python3 tools/backfill_cost.py'
# 核对 dry-run 的总额后再加 --apply
```

脚本按自身 `__file__` 解析 `src/`，所以必须放在项目树里，放 `/tmp` 会 `ModuleNotFoundError`。

## 部署后验证

```bash
# 服务活着
curl -s -o /dev/null -w "health %{http_code}\n" https://api.hhy.homes/health

# 路由在（未登录 302 是登录跳转，不是故障；404 才是路由没部署上）
curl -s -o /dev/null -w "admin %{http_code}\n"    https://api.hhy.homes/admin
curl -s -o /dev/null -w "members %{http_code}\n"  https://api.hhy.homes/members/2

# 接口存在（未登录应 401，带 code admin_denied）
curl -s https://api.hhy.homes/api/members | head -c 120

# 端口只在本机监听（对外必须经过 nginx）
ssh -i ~/.ssh/ubuntu.pem ubuntu@124.222.217.211 'ss -ltnp | grep 8791'
```

要验证登录后的页面内容，得带会话，见 `docs/本地调试.md` 里的临时实例做法——
那套方法同样可以接上 `ssh -L` 隧道来跑真实数据的页面。

## 回滚

所有部署都在目标文件旁留了 `.bak-<时间戳>`，直接覆盖回去再重启即可。

```bash
ssh -i ~/.ssh/ubuntu.pem ubuntu@124.222.217.211 '
  cd /opt/oh-pmt-api
  ls -t src/*.bak-* | head -5
  # cp src/server.py.bak-20261026-133949 src/server.py
  # sudo systemctl restart oh-pmt-api
'
```

数据库回滚要连 `-wal`/`-shm` 一起恢复，且必须先停服务，否则 WAL 里的新事务会覆盖回去。

## 看日志的规矩

```bash
ssh -i ~/.ssh/ubuntu.pem ubuntu@124.222.217.211 '
  cd /opt/oh-pmt-api
  ls -l logs/q2a.log
  systemctl show -p ActiveEnterTimestamp oh-pmt-api
  tail -50 logs/q2a.log
'
```

**先比对 mtime 与重启时间。** 如果日志 mtime 早于服务启动时间，里面的 Traceback
全是重启前的旧内容，与本次发布无关——这个误判真实发生过一次，白查了半天。
报错行号也要对得上当前文件，行号不匹配同样说明是旧日志。

成对出现的 `BrokenPipeError`（`stream_queue_notice` / `wfile.write`）是客户端提前断开
SSE 流，属正常现象。

## 安全边界

- 服务只监听 `127.0.0.1:8791`，对外靠 nginx + certbot 的 `api.hhy.homes`
- `PMT_TRUST_FORWARDED=1` 是因为前面有 nginx；换了没有反代的拓扑必须关掉，
  否则 IP 白名单可以被 `X-Forwarded-For` 伪造绕过
- nginx 必须 `proxy_buffering off` + 长超时，否则流式输出会被攒成一坨
- 生产库有真实成员与密钥。任何删除操作按主键限定，不要用可能被回收的 id
