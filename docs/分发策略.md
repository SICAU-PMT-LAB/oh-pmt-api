# 分发策略介绍

本文档详细阐明上游号池及模型合理分发给各个成员的逻辑，以及相关问题的回答。


## 上游稳定性排行

各模型的官方 api > 知名第三方 provider（opencode，commandcode，cline） > workbuddy-cn > workbuddy-global > qoder-cn > qoder-global > 福利账号。


## 账号成本

各模型的官方 API > 知名第三方 provider > 其他 ，福利账号的金钱成本为 0。


## 福利账号介绍

福利账号是指生效时间不确定（通常很短），账号成本极低，稳定性不确定，渠道各异的模型提供方式。通常具有及时性。可能包括别人送出的临期官方 api-key，中转推广的福利余额，他人分享的大量注册新号的反代等。

调用福利账号到模型不消耗成员限额用量但纳入数据统计。


## 分发策略（关键）

### 分配成功前

一般情况下应优先分配到稳定度高的上游，特殊情况如下：
规则1 福利账号 **如成员请求的模型在福利账号池中支持，优先调用福利账号池中的模型**。调用福利账号到模型不消耗成员用量。
规则2 固定优先账号 如成员被固定了优先账号,在不违背规则 1 的前提下，优先调用被固定的账号模型。

### 分配成功后

后续该模型请求不得随意切换到其他账号，除非调用遇到报错。
