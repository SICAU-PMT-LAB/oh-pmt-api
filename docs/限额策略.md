# 限额策略

Plan 和 API 是两种独立的限额策略，互不干扰。

## Apend-Only 原则

append-only 是指后续更新不影响先前已记录的价格。如更新模型定价或 plan 用户限额，都不得影响先前的计费和额度消耗。


## API

API 以余额模式限额，按模型价格表计算消耗，没有周限日限，余额耗尽立即停止。


## Plan
Plan 分为 go，plus，pro和 max四种档位
**默认**对所有模型的限额如下：

| 档位 | 日限额(元) | 周限额（元） |
| ---- | ---------- | ------------ |
| Go   | 5          | 25           |
| plus | 15         | 75           |
| pro  | 30         | 150          |
| max  | 50         | 250          |

上表只是档位级的总额。在它之上还有一层**按模型额度**，逐模型细分，四档共用同一套模型额度（写在 `src/plans.py` 的 `MODEL_LIMITS`，以 Plus 的数字为准，其他档按档位预算等比缩放）：

| 模型 | 日限额 / 周限额（元，Plus 档） |
| ---- | ----------------------------- |
| DeepSeek-V4.1-Flash | 20 / 100 |
| Step-5-Preview | 15 / 75 |
| GLM-5.3-Flash | 10 / 50 |
| MiniMax-M3.1-Flash | 5 / 25 |
| Xiaomi MiMo-V2.6-Pro | 5 / 25 |
| 其余开放模型（Kimi-K2.8-Preview、GLM-5.3、Hy4 preview、Kimi-K3.1-Pro、Qwen-3.8-Flash、Qwen-3.8-Max、DeepSeek-V4-Pro） | 3 / 15 |
| Hy3 | 不限额 |

Kimi-K3 与 Space-Bunny 不对成员开放（在 `pricing.RETIRED` 里）。

把某个模型的额度改小时，**不要只看金额**：池子是按百分比累加的（见下），一个 3 元的模型花完就是 100%。管理员可以按模型覆盖，覆盖值优先于 `MODEL_LIMITS`，且只影响之后的判断。

成员的 `limit_daily` / `limit_total` 仍是总量封顶：模型额度会按「成员额度 ÷ 档位额度」等比缩放，所以给成员设了个位数的日限不会被 deepseek 的 20 元额度盖掉。

管理员可具体到每个模型更改限额策略（更改不影响先前计费，append-only，日限周限 1:5 不是绑定关系）

Plan 的计费通过对每个模型的限额计算额度百分比，达到 100% 则停止调用，公式如下：
$$
\theta = \sum_{i=1}^{n} \frac{\text{(单调用消耗)}_i}{\text{(模型限额)}_m} \times 100\%
$$
θ 为消耗额度百分比。单模型消耗 i 按照调用数据对照模型价格表计算消耗成本。

### 举例：

背景：用户 A 可用 3 个模型，模型 1 日限额 15 元，模型 2 日限额 5 元，模型 3 日限额 50 元。

事件：用户先使用 25 元的模型 3，再使用 1 元的模型 2，最后使用了 3 元的模型 1。

推导：使用 25 元模型 3 消耗 25 / 50 * 100% = 50% ，用户还剩下 50% 日限额；使用 1 元模型 2 消耗 1 / 5 * 100% = 20%，用户还剩下 30% 日限额；使用 3 元模型 1 消耗 3 / 15 * 100% =  20%， 用户只剩下 10% 日限额。

结论：用户消耗了 90% 的日限额，剩余 10% 日限额，可用于调用 1.5 元模型 1 或 0.5 元模型 2 或10 元模型 3。周额度同理计算。但如果之后将模型 2 日限额改为 100 元，先前已记录的 20% 消耗不变，之后的消耗按修改后计算。

不限额的模型（Hy3）额度记 0，没有分母，不计入这个求和，它的花费也不推进池子。

注意：日限额或周限额任意一项达到 100% 则停止调用，等待重置。
