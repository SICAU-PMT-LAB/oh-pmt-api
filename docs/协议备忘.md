# 协议速查

从 `pi-provider-qoder-0.4.6`（官方扩展，2195 行）与 `qoder2api-hub`（v1.7.1）提取，
两者 RSA 公钥逐字符一致。完整说明见 `../CONTEXT.md`。

## 不需要签名的端点

| 用途 | 请求 |
|---|---|
| PAT 换 job token | `POST {openapi}/api/v1/jobToken/exchange`，body `{"personal_token":"pt-..."}` |
| 取账号信息 | `GET {openapi}/api/v1/userinfo`，`Authorization: Bearer {jobToken}` |
| 刷新令牌 | `POST {openapi}/api/v1/jobToken/refresh`，body `{"refresh_token":"jrt-..."}` |

这三个只带 `Content-Type`、`Accept`、`Cosy-Version`、`Cosy-ClientType`。

## 需要签名的端点

| 用途 | 请求 |
|---|---|
| 模型列表 | `GET {base}algo/api/v2/model/list?Encode=1` |
| 对话 | `POST {base}algo/api/v2/service/pro/sse/agent_chat_generation?FetchKeys=llm_model_result&AgentId=agent_common&Encode=1` |

## 凭证时效

PAT（`pt-`）长期有效，但换来的 job token 只有 24 小时，refresh token 48 小时。
**长期运行必须实现刷新**，否则账号一天后失效。刷新失败时回退到 PAT 重换。

## 签名要点

`Authorization: Bearer COSY.{payload_b64}.{sig}`

```
aes_key   = 16 位随机（key 同时作 IV）
info_b64  = base64(AES-CBC({uid, security_oauth_token, name, aid, email}))
cosy_key  = base64(RSA_PKCS1v15(aes_key))
payload   = {cosyVersion, ideVersion:"", info, requestId, version:"v1"}
payload_b64 = base64(JSON，sort_keys)
sig       = md5(payload_b64 \n cosy_key \n timestamp \n body_bytes \n sig_path)
sig_path  = 请求路径去掉 /algo 前缀
```

关键头：`cosy-key`、`cosy-user`、`cosy-date`、`cosy-machineid`、`cosy-machinetoken`、
`cosy-bodyhash`、`cosy-bodylength`、`cosy-sigpath`、`cosy-clienttype: 5`。

## 请求体编码

标准 base64 后按 `a = n//3` 切三段，重排为 `尾 + 中 + 首`，再用自定义 64 字符表替换，
`=` 换成 `$`。字符表见 `src/cosy.py` 的 `CUSTOM_ALPHABET`。

## 响应结构

模型列表返回 `{"chat":[{key, display_name, enable, is_reasoning, context_config, ...}]}`。

对话返回 SSE 信封，内层就是 OpenAI chunk：

```
data:{"headers":{...},"body":"{\"choices\":[{\"delta\":{...}}]}","statusCodeValue":200}
data:{"body":"[DONE]"}
```

所以转换层只需要拆信封，不用重新构造 chunk。

## 升级时改哪里

Qoder 客户端升级后若请求被拒，优先检查 `Q2A_COSY_VERSION`（当前 `1.1.75`）。
其次核对 `CUSTOM_ALPHABET`、RSA 公钥、必需头列表是否变化。
