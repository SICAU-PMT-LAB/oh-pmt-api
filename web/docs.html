开始

Prometheus API 是 Prometheus Lab 社团维护的模型接入服务。它对外暴露一套 OpenAI 兼容接口，把社团统采的几个上游账号池封装成一个 base_url，再用 API Key 分发给成员。

你能用的模型取决于社团开给你的白名单，成本从你账户的日额度与周额度里扣。任何能配置 OpenAI 兼容 base_url 的客户端都能用：Pi、Codex、Zcode、DeepSeek Harness、Hermes、Claude Code 等，或者你自己写的脚本。

接入

三步：拿到 Key，配好 base_url，选一个模型名。

  1. 向社团负责人申请账号，你会得到一个 sicau-PMT- 开头的 API Key。
  2. 把 https://api.hhy.homes/v1 当作 OpenAI 的 base_url，把 Key 当作 api_key。
  3. 模型名直接用 GET /v1/models 返回的 id，大小写不敏感。
curl https://api.hhy.homes/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sicau-PMT-..." \
  -d '{
    "model": "DeepSeek-V4.1-Flash",
    "messages": [{"role": "user", "content": "写一个快排"}],
    "stream": true
  }'
先验一下 Key。GET /v1/models 只需要 Key 不需要花额度，用它就能确认 Key 是否有效、能看到哪些模型。

模型

同一个模型背后可能有好几家上游。对外只暴露一个名字，网关按顺序尝试：优先账号所属的那家先试，它连不上就换另一家重连，对客户端始终是一条流。

客户端配置

Pi-Agent

把下面的片段并进 ~/.pi/agent/models.json，把 models 数组换成你要用的模型名。

{
  "providers": {
    "prometheus": {
      "baseUrl": "https://api.hhy.homes/v1",
      "api": "openai-completions",
      "apiKey": "$PMT_API_KEY",
      "models": [
        { "id": "DeepSeek-V4.1-Flash" },
        { "id": "GLM-5.3-Flash" }
      ]
    }
  }
}

OpenAI SDK

from openai import OpenAI

client = OpenAI(
    base_url="https://api.hhy.homes/v1",
    api_key="sicau-PMT-...",
)
print(client.chat.completions.create(
    model="DeepSeek-V4.1-Flash",
    messages=[{"role": "user", "content": "hi"}],
).choices[0].message.content)

环境变量

很多 CLI 工具直接读这两个变量，设好就能用：

export OPENAI_BASE_URL=https://api.hhy.homes/v1
export OPENAI_API_KEY=sicau-PMT-...

流式与思考

SSE 开写之后就不能再补发 HTTP 错误响应，所以流已经开始时的上游故障会以一条 data: {"error": ...} 事件收尾，随后是 [DONE]。客户端要把这种事件当成错误显示。

思考档位用 reasoning_effort 传。上游对不认识的档位不报错，而是静默忽略；finish_reason 为空的块会被归一成 null。

额度

额度按成本计算，不按请求次数：每次请求的输入、输出、缓存读、缓存写各自按单价折算成人民币累加。

额度是按模型算的，按份额累加：每个模型有自己的日额度与总额度（默认等于你档位那一份，例如 Plus 是每日 ¥15、总额 ¥75），一次调用占用「本次金额 ÷ 该模型额度」那么多份额，各模型份额加起来到 100% 就用完了。

举例：a 额度 ¥100、d 额度 ¥10。a 花 ¥50 占 50%，再花 d ¥4 占 40%，合计 90%，还剩 10%——这 10% 既可以继续花 ¥10 在 a 上，也可以花 ¥1 在 d 上。所以档位那个金额是对外口径，实际能用多少看份额。某个模型自己先到 100% 时只停那一个模型。四个档位的具体数值见 Plan。

  • 日额度：本地时间 0 点重置。
  • 总额度：不重置，按累计消耗算。
  • 限额为 0 表示不限。管理员可以给某个成员单独调小某个模型的额度，调小只影响之后能用多少，已经发生的用量不会变。

控制台的 模型 页可以看到每个模型的单价、额度与已用百分比。

账号与密码

账号由管理员在后台创建，初始密码会当面或私下告知。登录后可以在成员控制台自行改密码；管理员看不到你改后的密码，只能把你重置成初始密码。

API Key 在成员控制台自己创建，分两条通道：PLAN 按档位额度算，API 按赠礼余额算，两边互不影响。明文只在生成的那一刻显示一次，之后数据库里只有 sha256，谁也取不回原文。丢了就删掉重建一把新的。

HTTPcode含义

403model_forbidden这个模型没开给你的 Key

429quota_daily_exceeded今日额度已用满，本地时间 0 点重置

429api_balance_exhaustedAPI 通道余额不足，需要管理员发放
429login_locked登录尝试次数过多，稍后再试

隐私

我们只保存计费需要的元数据，不保存请求与响应的正文。

  • 存：模型名、输入/输出/缓存 token 数、折算成本、状态码、来源 IP、时间戳、所属成员与账号。
  • 不存：消息正文、系统提示词、工具调用参数、模型输出、文件内容、代码片段。
  • 不用于训练：任何保存下来的字段都不参与模型训练或微调，我们也没有把数据导出给第三方的通道。
  • 公开看板：Data 页只展示聚合后的 token 与成本，成员以序号出现，不含姓名、邮箱和密钥。

常见问题

模型名大小写敏感吗？

不敏感。deepseek-v4.1-flash 与 DeepSeek-V4.1-Flash 指向同一个模型，但建议用 /v1/models 返回的写法。

为什么我的请求返回 429？

先看返回的 message：写「日额度」就是当天用满了，等本地 0 点；写「周额度」就是本周用满了，等下周。upstream_busy 是账号池暂时没有可用账号，过一会儿重试即可。

能同时开多个并发的代理吗？

可以，额度按成本累计，并发不额外限制。但并发太多时上游账号池可能排队，表现为延迟升高而不是报错。

可以把 Key 分享给同学吗？

不建议。额度按 Key 累计，分享出去等于把配额和封禁风险一起交出去。每人一把 Key 才能看到各自的用量。

为什么某个模型突然不见了？

上游下线某个模型时，网关会把它从 /v1/models 里摘掉，避免客户端选到跑不通的名字。历史账目不受影响。
